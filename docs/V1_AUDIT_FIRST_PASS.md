# v1.0 第一轮实现审计

原始文档为 `EnglishLearningApp_v1.0_Codex完整开发任务.docx`，完整正文含表格共 204 段、22 章。原始文本逐段保存在 [original-requirements.txt](audit/original-requirements.txt)，拆分后的 318 条验收项及逐段覆盖映射在 [acceptance.json](audit/acceptance.json)。章节、表头等结构段也保留映射，没有静默略去。

审计基线：`19bd6d46a216c400de6cb1fdc81d8d4537abbbea`，即 Secrets 配置后正式构建成功的版本。回滚分支：`backup/pre-v1-functional-audit-20261023`。本轮不改变 applicationId 或固定正式证书。

本轮先沿真实入口 `MainActivity → AdaptiveApp → AdaptiveViewModel → AdaptiveRepository` 检查调用链，再检查数据库提交、算法输入、AI 传输边界和真实题库。第一轮的完整逐项状态见最终表的“首轮”列；以下是导致“部分实现/未实现”的具体原因。

| 问题 | 基线代码与实际缺口 |
|---|---|
| 间隔并未直接考虑全部规定历史因素 | `AdaptiveReview.update` 保存 lapses/streak，但 growth 没有直接使用它们；不能把字段存在等同于参与算法。 |
| 大部分词难以达成多语境掌握 | `LocalContent.vocabulary` 主要复用一条例句；`WordNotes` 仅 20 词有第二语境，而 mastered 要求至少两个语境。 |
| 卡片内容覆盖不足 | 全词库保留原例句，但离线常见搭配/必要词形仅有 20 词补充；没有逐词的高考适配校核。 |
| 时间预算偏低 | `DailyPlanner.calculate` 只为阅读和小测等保留 5 分钟；自定义短时仍安排完整阅读和 15 题。 |
| 学习中切换强度不完整 | `AdaptiveViewModel.mode` 只裁减剩余新词，阅读、小测不会随快速模式收缩，也不能可靠恢复强化任务。 |
| 小测历史词来源不准确 | `WorkflowFactory.create` 用到期 reviews 作为历史池；存在已学但未到期词时仍可能回退到新词。 |
| 语法小测可能重复题干 | 同一弱项两道小测题使用相同索引，仅换题目 ID。 |
| 新词正确率由槽位推断 | `performance` 用 `:quiz:new:` 标记识别新词；回退到复习词后可能被误记为新词表现。 |
| 明日计划的保存依赖 AI 按钮 | 本地次日算法能计算，但完成当日后没有独立自动保存明日计划；预生成又可能复用过早计算的旧计划。 |
| 阅读按日期归组 | `skills/summary` 把日期当作篇章，无法准确区分同日不同文章，也没有独立长期与近期题型结果。 |
| 前后台计时丢失 | `foreground/start` 重置 entered，暂停或后台前已经花的时间没有正确累计/恢复；每题硬截到 10 分钟。 |
| 优先弱项不含词汇能力 | `skills` 只聚合 reading/grammar，拼写和语境薄弱无法进入全局 1～3 个最高优先项。 |
| 无样本仍显示 75% | 诊断页显示排程缺省值，虽有提示，仍不是用户真实拼写成绩。 |
| 阅读错误缺少语法验证链 | 记录“句子结构”错因后没有真实语法验证题，无法由阅读困难产生可靠知识点证据。 |
| AI 针对性练习未接入真实评分 | 原 AI 讲解中的 suggestions 是文字建议；原词汇小测不能覆盖真实阅读/语法弱项。 |
| 提前查看全篇解析会泄漏未答题答案 | `WorkflowScreen` 在阅读作答前可展开全文缓存。 |
| 实际模型缺失时被请求模型代替 | `AiClient.generate` 以 requested model 兜底，不能证明实际响应模型。 |
| 缺失缓存分项和真实 0 无法区分 | `TokenUsage` 没有字段可用性记录，界面把未返回缓存分项显示成 0。 |
| 无效内容的请求状态失真 | 返回了真实 usage 但 JSON 校验失败时，账目可能仍显示 OK。 |
| 音频文件操作仍在主线程 | `SpeechController.playLocal` 的文件访问和 setDataSource 在主线程，prepareAsync 并不能消除前面的 I/O。 |
| 页面缺少轻量过渡 | 实际 route 使用普通 when 切换，没有过渡逻辑。 |
| 迁移/导入校验仍有缺口 | 旧 v5 快照、阅读标识和新增账目元数据需独立升级；导入对记忆参数范围与孤立记录验证不够。 |
| 二级设置仍展示断签归零的连续天数 | `UpgradeMe` 旧重复统计仍展示连续学习天数；移除这一压力展示，统计以诊断页为准，不删除历史数据。 |
| 用户设置可能被强制覆盖 | `StudySettingsStore.init` 首次设置 heart_audio_v1 时可能覆盖已有 speak=false，而规格要求优先保护可靠自定义设置。 |
| 阅读/语法资源较少 | 仅 3 篇基础短文与 3 个语法知识点 / 12 题，不能声称已有完整高考真题库。 |

已存在的真实功能不因本轮重构被否定：分层主动回忆、三档自评、部分随机抽查、客观评分写回、核心 SQLite 事务、离线发音、统一调度类、手动 AI 工具、基本缓存与费用、升级前备份、单层底部导航等，在基线已经有实际调用链。完整状态不以页面、接口或测试名字推断。

## 必须明确的资源边界

原文没有要求宣称“官方高考真题”。本轮新增阅读材料应明确标注原创分级训练。词条常见搭配和高考例句的全量可靠校核不能靠从一句语料截取片段或自动拼接词形来冒充。缺少可核验资源时保留“部分实现”，不通过改低验收标准把它变成完成。
